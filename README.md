# flyloop

**Does a generated world move the way a real one does? Ask something that has been answering that question for 400 million years.**

flyloop connects a *Drosophila* escape circuit to AI-generated worlds and measures whether the
circuit reacts the way it does to real approaching objects.

---

## the problem

World models now generate environments you can walk through, drive in, and steer in real time.
They are starting to be sold as places to **test robots** — Reactor took NVIDIA money in October
to build exactly that.

But nobody can say whether a generated world *behaves* correctly, only whether it *looks*
correct. The current state of the art for judging that is:

- **human eyeballs** — "it's literally just look at it and human judgment… including DeepMind.
  Nobody has solved this problem yet." (Ahmed Ahres, Reactor, AI Engineer 2026)
- **a VLM quiz** — NVIDIA's HUE decomposes a clip into yes/no questions about physical laws,
  generated by a VLM pipeline and refined by humans.

Both judges are a human, or a model trained on human labels. If you are going to validate a
robot policy inside a hallucinated world, "a language model thought it looked fine" is not a
safety argument.

## the idea

A fly does not segment objects or estimate depth. Its escape circuit reads raw optic flow across
a hex array of ommatidia and fires when something is about to hit it. That circuit is *measured*,
not trained — the wiring comes from the male-CNS connectome, and the dynamics are unfitted.

So we point it at generated video and ask when it panics.

```
world model  ->  frames  ->  fly's-eye retina  ->  escape circuit  ->  spike?
                                                         vs
                               frames  ->  segment object  ->  theta(t)  ->  threshold
                                                   (the honest baseline)
```

## what this measures — and what it does not

**Measures:** whether the apparent size and optic flow of an approaching surface evolve the way
projective geometry says they should, and whether that holds across approach speeds and repeats.

**Does not measure:** gravity, mass, friction, collision response, or whether a policy trained
in the world will transfer. A wall can expand perfectly and still have nonsense collision physics.

So this is not "a physics evaluator." It is a **geometric-consistency probe for generated video**,
with a biological detector as the instrument. We would rather ship a narrow claim that holds.

## the experiment that makes or breaks it

You can compute optical expansion with three lines of trigonometry. So why a connectome?

That is the right question, and it is the headline experiment rather than an assumption:

| detector | input | needs object segmentation? | free parameters |
| --- | --- | --- | --- |
| analytic baseline | frames | **yes** | threshold |
| fly circuit | raw retinotopic luminance | **no** | none (unfitted) |

The baseline has to *assume the geometry it is testing for* — you segment the object, estimate
size over distance, and compare against the model you are trying to validate. It is partly
circular. The fly path never segments anything.

So the interesting signal is **where the two disagree**: clips whose global geometry looks right
while the local flow field does not cohere. We run both on every clip and report the gap.

If the fly adds nothing over trig, that is a real result and we will say so.

## calibration ladder

Every number is meaningless without a known-correct and a known-broken case, so we build those
first and offline:

1. **analytic looming** — a sphere approaching at constant speed, `theta(t) = 2*atan(R/d(t))`.
   Ground truth is exact. The probe must report the published threshold here, or the instrument
   is broken.
2. **deliberately broken** — linear expansion instead of hyperbolic, a mid-approach size jump,
   a time-reversed (decelerating) profile. We know these are wrong, so the detector must say so.
3. **real video** — a genuine approach.
4. **generated** — Reactor (LingBot World 2, Helios), Marble, Veo.

Marble is the useful one for calibration: it returns Gaussian splats, a collider mesh and metric
scale, so we know true depth and can fly a camera at an exactly known speed.

## results so far

All offline, on clips whose geometry is known in closed form. `python scripts/run_synthetic.py`.

**The circuit behaves like the animal.** Across an 8x approach-speed sweep (0.25 to 2.0 m/s)
the escape commits at **20.97 +/- 1.24 deg**. The behavioural literature puts the escape
threshold near 20 deg (Ache et al. 2019).

**But there is a tradeoff, and it is the most interesting thing we found.** The same
circuit cannot be both stable and sensitive:

| configuration | threshold SD over 8x speed | lead over the trig baseline on broken clips |
| --- | --- | --- |
| invariant (normalised) | **1.24 deg** | 1.0 frames |
| sensitive (raw) | 4.95 deg | **5.0 frames** |

Normalising the circuit for speed invariance turns its pooled drive into "what fraction of
the field is expanding", which *is* angular size — so it converges on the analytic baseline
and stops catching clips whose expansion profile is wrong. Back the normalisation off and
it catches them, but its threshold slides with speed.

So the honest answer to "why not three lines of trigonometry" is: **at one end of this
curve, there is no reason — they are the same detector.** The fly only earns its keep at
the other end, where it fires 5 frames ahead of trig on an approach that is smoothly,
plausibly wrong.

**How the animal escapes the tradeoff.** It does not use one channel. Two visual
projection populations converge on the giant fibre and are tuned to different things: LC4
to angular velocity, LPLC2 to angular size (Ache et al. 2019). That asymmetry is what makes
the pair a size-and-speed detector when neither is one alone. We built both channels and
summed them with the published weights, and the result sits off the single-channel frontier:
**1.41 deg** spread with a **3.33 frame** lead on broken clips, where the frontier at that
stability allows only about 1.2.

## pipeline

Both sponsors, one chain. Reactor is required; the seed image is required by Reactor.

```
Nano Banana 2.1 (ai.studio)  ->  seed image: one obstacle, dead ahead
            |
LingBot World 2 (Reactor)    ->  set_image, set_prompt, start,
            |                     then set_move_longitudinal: forward
       approach video
            |
          flyloop            ->  fly's-eye retina -> escape circuit
                                 vs the trig baseline -> threshold, lead, agreement
```

MiniMax FastH3 is the secondary capture path: it is built for one long continuous take
where the last frame seeds the next, which is what a looming event needs — it must never
cut.

## fool the fly

The benchmark is also a game. Prompt LingBot World 2 and try to generate an approach the
circuit *misses*, or catches at the wrong angle. Every win is a physics failure, found by
a person playing, logged automatically. Red-teaming a world model by having fun with it.
